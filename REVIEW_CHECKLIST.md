## 🔴 Критично — логика денег и склада

### Продажи
- [ ] **`confirmCart` не проверяет остаток** — `sklad-backend/src/modules/sales/sales.service.js:201`. Боевой путь POS списывает `decrement` без проверки наличия → склад уходит в минус. (В `create` проверка есть — стр. 46, в `confirmCart` нет.)
- [ ] **`confirmCart` не в транзакции** — `sales.service.js:196-217`. Списание остатков + завершение продажи + создание долга = отдельные запросы. Сбой посередине → битое состояние. Обернуть в `prisma.$transaction` (как `create`/`cancel`).
- [ ] **Параллельные корзины не резервируют товар** — один товар в 2 чеках подтверждается дважды → двойное списание. Решается проверкой+транзакцией выше (либо резервом остатка на PENDING).

### Приход
- [ ] **Нет валидации входных данных** — `sklad-backend/src/modules/products/stockin.routes.js:37`. Пустое `quantity` → `parseInt(undefined)=NaN` → `increment: NaN` **портит остаток**; пустая цена → `buyPrice=NaN`. Добавить проверку `qty>0`, `price>0`, существование товара.

### Аналитика
- [ ] **`getTopProducts` без фильтра статуса** — `analytics.service.js:80`. Считает позиции из корзин (PENDING), отменённых и возвратов. ✅ вживую: топ показал 9345 ед. при 17 завершённых продажах. Фильтровать по `sale.status = COMPLETED`.
- [ ] **`getTopProfitProducts` — двойная ошибка** — `analytics.service.js:97`: (1) нет фильтра статуса; (2) прибыль = `(текущий sellPrice − текущий buyPrice) × кол-во` вместо фактической цены продажи и исторической закупки. Считать по `SaleItem.price` завершённых продаж.
