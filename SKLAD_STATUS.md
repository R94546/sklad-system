### POS — экран оплаты (СЕССИЯ 2026-06-07) ✅
Реализован прямо в `POS.jsx` как режим `view = "payment"` (тот же тёмный навбар, без миграций БД).
- **Способы оплаты** списком: Наличные / Карта / Долг (счёт клиента). Клик добавляет платёж на остаток.
- **Цифровая клавиатура** + **быстрые суммы +100 / +500 / +1000** (зелёные).
- **Смешанная оплата**: несколько платежей, живой остаток («Осталось», красный) и **сдача** (зелёная, при переплате наличными).
- Маппинг на бэкенд `confirmCart` без миграций: только наличные→CASH, только карта→CARD, есть долг→DEBT, долг+другое→MIXED (`debtAmount` = сумма долга). Для долга — выбор клиента + срок.
- Кнопка «Подтвердить» активна только когда остаток ≤ 0. Кнопка «Назад» возвращает в чек.
- Order-level скидку убрал — скидки делаются по позициям через режим «%» клавиатуры (ближе к Odoo). Временный модал оплаты удалён.
- Проверено: `vite build` ✓, `eslint` ✓.

> ⚠️ Ограничение текущей схемы: комбинация Наличные+Карта (без долга) пишется одним `paymentType` (CASH) — раздельный учёт способов появится с моделью `Payment[]` (будущая миграция). Сдача нигде не сохраняется (только показывается кассиру).

### POS — экран подтверждения оплаты (СЕССИЯ 2026-06-07) ✅

### БОСКИЧ — Аудит-ревью + дофиксы (СЕССИЯ 2026-06-11) ✅
Большое ревью логики/UX по всем доменам (см. `REVIEW_CHECKLIST.md` — детальный чек-лист с отметками). Сделано:

**🔴 Целостность денег/склада (backend):**
- `confirmCart`/`kassaConfirm` обёрнуты в `prisma.$transaction`; списание остатка — **атомарным условным decrement** (`updateMany where quantity>=qty`, проверка `count`) → защита от ухода в минус и гонки параллельных чеков. Проверено вживую (перепродажа отклоняется без минуса).
- `cancel`/`remove`/`kassaReturn` — транзакция + возврат остатка только для `COMPLETED` (раньше PENDING/отменённые задваивали склад); `remove` чистит связанный долг.
- Приход: валидация (qty>0, price≥0, товар существует) — раньше пустое поле давало `NaN` и портило остаток.
- Аналитика: `top-products`/`top-profit` фильтруют `status=COMPLETED` (раньше считали корзины/отмены); прибыль по фактической `SaleItem.price`.

**🟠 Архитектура/важное:**
- `sales`/`analytics`/`stockin` переведены на **синглтон** `config/db.js` (раньше свои `PrismaClient` → утечка пула).
- **Все** backend-сообщения русифицированы (auth/sales/products/categories/clients/users/barcode/upload/middleware).
